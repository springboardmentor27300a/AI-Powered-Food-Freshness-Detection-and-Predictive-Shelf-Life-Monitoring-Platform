# CNN Training Guide

## Requirements

- Python 3.10–3.12 (matches your existing Milestone 1 backend venv)
- Dependencies from `backend/requirements.txt` (the ML-specific ones:
  `tensorflow-cpu`, `scikit-learn`, `matplotlib`, `numpy`, `opencv-python-headless`, `Pillow`)
- ~3GB free disk (dataset + processed copies + saved model)
- No GPU required — MobileNetV2 transfer learning is deliberately chosen
  because it trains in a reasonable time on CPU

## Folder structure this expects

```
backend/ml/
  data/
    raw/            <- you put the unzipped Kaggle dataset here
    processed/       <- generated by prepare_dataset.py
      train/fresh, train/rotten
      validation/fresh, validation/rotten
      test/fresh, test/rotten
  training/
    prepare_dataset.py
    train_cnn.py
    evaluate_model.py
  inference/
    freshness_predictor.py   <- used by the FastAPI backend, not run directly
  models/           <- trained model + metrics land here
  config/
    class_names.json
```

## Step-by-step (PowerShell, Windows 11)

```powershell
cd backend
.\venv\Scripts\Activate.ps1          # your existing Milestone 1 venv
pip install -r requirements.txt      # picks up the new ML dependencies

# 1. Download the dataset (see docs/DATASET.md) into backend/ml/data/raw/

# 2. Organize it into train/validation/test with no leakage
python ml/training/prepare_dataset.py

# 3. Train (transfer learning on MobileNetV2)
python ml/training/train_cnn.py

# 4. Evaluate on the held-out test set — real metrics, not estimates
python ml/training/evaluate_model.py
```

## What each script produces

| Script | Output |
|---|---|
| `prepare_dataset.py` | `ml/data/processed/{train,validation,test}/{fresh,rotten}/*.jpg` |
| `train_cnn.py` | `ml/models/freshness_model.keras`, `ml/models/class_indices.json`, `ml/models/training_history.png` |
| `evaluate_model.py` | `ml/models/evaluation_report.json` (accuracy/precision/recall/F1/confusion matrix), `ml/models/confusion_matrix.png` |

Once `freshness_model.keras` exists, the backend picks it up automatically
the next time it loads a prediction request — no backend restart logic
needed beyond `ml/inference/freshness_predictor.py`'s lazy load. Check
`GET /api/images/model-status` to confirm the API sees it as available.

## Expected training time (CPU)

Rough guide on a typical modern laptop CPU (varies with hardware):
- Stage 1 (frozen backbone, 10 epochs): ~1–3 min/epoch → 10–30 min total
- Stage 2 (fine-tuning, 5 epochs): slightly slower per epoch since more
  layers are trainable → 10–25 min total
- **Total: roughly 20–60 minutes** for the full ~13.5k-image dataset

If that's too slow: reduce `EPOCHS_HEAD`/`EPOCHS_FINE_TUNE` or `BATCH_SIZE`
at the top of `train_cnn.py`, or set `FINE_TUNE = False` to skip stage 2
entirely (you'll get a slightly less accurate but much faster model).

## Inference command (sanity check outside the API)

```powershell
python -c "from ml.inference.freshness_predictor import predictor; from pathlib import Path; print(predictor.predict(Path('path/to/some/test/image.jpg')).__dict__)"
```

## Honesty notes

- The model is trained on **2 real classes** (fresh/rotten) from a real,
  named, public dataset — not simulated data.
- `evaluate_model.py` reports metrics computed on the actual `test/` split,
  which was never seen during training or validation.
- If `freshness_model.keras` doesn't exist yet, `freshness_predictor.py`
  returns `status: model_unavailable` with the exact reason — the API and
  UI show this honestly rather than fabricating a prediction.
